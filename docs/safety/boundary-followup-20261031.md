The oracle worktree is untouched.

1. **IND-MEM-FIRSTBUF (P1):** `ch_get` checks the empty LRU sentinel before any buffer cast or hash-link access. A missing first buffer diagnoses once and latches failure; later reads stop, and eventual successful quit becomes status 1 while specific primary errors survive. Allocation failure with existing buffers still reuses the LRU buffer. `tools/safety/test_first_buffer.py` checks exact control/wrong-range bytes, selected first ENOMEM (one diagnostic, no panic, zero copied bytes, status 1), and selected second ENOMEM (complete bytes through buffer reuse). The companion test-only linked object is `tools/safety/native/first_buffer_fault.c`; it selects an exact `ch_addbuf` caller range and forwards other allocations.
2. **IND-MEM-STDIN-DELETE (P1):** `del_ifile` releases its own retained filestate and buffer list through `dispose_ifile_state`, independently of the active input. It detaches the owner and any matching active alias before freeing. CH_KEEPOPEN descriptors, including stdin fd0, remain borrowed; pipe/help owners retain their separate close policy. The delete command already switches successfully before deleting the old ifile and needs no change. The lifetime unit case checks active/inactive aliases, repeated disposal and borrowed descriptor survival; `tools/safety/test_stdin_delete.py` retains the independent PTY comparison of `:n` and `:d`, now requiring both to exit 0 without LSAN leaks and with matching screens and restored termios. Run it with the pinned `RLESS_SAFETY_ENV` for actual leak detection; a native run is only a behavioral smoke check.
3. **IND-FD-F3 (P3):** tty acquisition now returns an explicit descriptor and ownership flag. `lsystem` closes acquired tty descriptors even in standard slots, and leaves borrowed fd2 fallback open. The supplemental boundary suite adds `fd-tty-owned-2`, forcing the shell tty open into fd2 and requiring the helper to observe that owner closed after stdin replacement; existing fallback checks remain unchanged. Failure diagnostics retain the existing handoff policy; this disposition concerns descriptor ownership, not an independent UI reporting qualification.
4. **IND-POS-F4 (P3):** position-table logical rows are tracked separately from allocation capacity. Shrink discards removed rows; regrowth cannot resurrect old positions, including growth beyond capacity. Preallocation growth scans use only the prior logical rows. The existing single global-state position test now covers a stale sole anchor below a shrink, regrowth within and beyond capacity, and preservation of a valid top anchor.
5. **F5 deliberate compatibility changes:** logical terminal height is at least two (one content row plus prompt/position sentinel), including `LESS_LINES=1` and physical one-row terminals. Nonpositive effective heights retain the prior 24-row fallback before this minimum is applied. `LESS_SHELL_LINES` is clamped into `[1, sc_height-1]`, including zero/negative settings. These are intentional differences for unsupported geometry; they prevent invalid position indexing. Frozen compatibility expectations and detector settings are unchanged. Existing supplemental one-row and growth cases document the resulting behavior.
